# PostHog on the published site

Slug: `posthog-integration`

## Goal

The PostHog setup merged in #3 (generated by the PostHog wizard) must actually collect data from the production site on GitHub Pages, with working autocapture, while the app keeps starting without any analytics configuration.

## Findings before the change (2026-11-12)

- The Pages workflow ran `npm run build` without PostHog variables. The deployed `a50d06c` build had no project token and its CSP had no PostHog domain, so `posthog.init` never ran in production: no events at all.
- `defaults: "2026-08-30"` sets `capture_pageview: 'history_change'` (pageviews only on pathname changes) and `disable_capture_url_hashes: true` (hash stripped from `$current_url` and related URLs). With `HashRouter`, every screen would be reported as the site root and only the first pageview would be captured. Checked in `posthog-js@1.447.14` sources and `@posthog/types` docs.
- In dev mode a missing variable threw at import time, so `npm run dev` without a local env file showed a blank page (participants never have one).

## Scope

- `.github/workflows/pages.yml`: build step receives `VITE_PUBLIC_POSTHOG_PROJECT_TOKEN` and `VITE_PUBLIC_POSTHOG_HOST` from repository Actions variables (`vars.*`). CI unchanged (no analytics in tests).
- `src/lib/posthog.ts`: `capture_pageview: { path: true, hash: true }`, `disable_capture_url_hashes: false`; missing configuration logs one console warning in dev instead of throwing (silent in unit tests).
- `.env.example` (committed, `!.env.example` in `.gitignore`) and a local, gitignored `.env.development` with the owner's EU host and project token. `.env.development` instead of `.env` because Vite also loads `.env` for production builds and vitest; the local `./scripts/verify` browser journeys assert no external requests and a strict CSP.
- `FEATURES.md` SYS-03/SYS-11/SYS-13 and limits, `docs/RELEASE.md` (variables, setup, smoke check step 9), `docs/SECURITY.md`.

Out of scope: consent dialog or cookieless mode, the in-app privacy page text (PUB-09 still says there is no real data processing), sending error messages through `captureException`, PostHog project settings.
